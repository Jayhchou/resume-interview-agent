# 手工测试指引（你自己跑一遍用）

> 目标：20 分钟内把主链路走完，每一步都能当场判断「过 / 不过」。
> 环境：Windows + Edge（最新版）+ 本地服务 `http://127.0.0.1:8000`
> 分数会随模型波动，别拿绝对分当标准，看**结构对不对**（几轮、几条、有没有跳转）。

## 二、第 1 步：粘贴解析（2 分钟）

**操作**：模板选择页 → 展开「或者粘贴简历文本」→ 粘全文 → 点「解析这段文本」。

**预期**：

| 检查点 | 预期结果 | 这轮实际（有问题） |
| --- | --- | --- |
| 进入编辑器 | 自动跳到「结构化简历编辑」，左侧 6 个模块、右侧 A4 预览 | ✅ |
| 姓名/求职意向/邮箱 | 三格都填上 | ✅（电话没解析出来，小问题） |
| 教育背景 | 学校、专业、本科、GPA 都在，**日期只出现一次** | ❌ 日期出现两次 |
| 实习经历 | 公司 = 某电商公司、岗位 = 后端开发实习生、时间段 = 2022.07-2022.12，要点 **2 条** | ❌ 公司变成 `2022.07`，多出一条 `- 2022.12 某电商公司` |
| 技能 | **5 个 chip**：Java / Spring Boot / MySQL / Redis / Git | ❌ 变 6 个，`Spring Boot` 被拆成两个 |
| 左栏模块计数 | 技能显示「5 项技能」 | ❌ 刚进来显示「0 项技能」，点一下模块才变 6 |

> 判定：第 1 步现在必然不过（3 处错位）。你手工跑时不用反复试，记下来即可。

## 三、第 2 步：五维诊断（约 25 秒）

**操作**：点右上「五维图分析」。看到「正在逐维找原文证据…」的进度提示。

**预期**：

| 检查点 | 预期结果 |
| --- | --- |
| 耗时 | ≤ 40s（本轮 24s） |
| 总分 | 出现一个 0–100 的分 + 等级（推荐/良好…），本轮 72 |
| 五维分 | **不要全部相同**，雷达图应该是歪的五边形（本轮 6/8/8/6/7，是正常样子；如果 7/7/7/7/7 则是问题） |
| 扣分证据 | 每条带**原文引用**（「」包住简历原句）+ 为什么扣分 |
| 最该先练 3 条 | **首次诊断就出现，不需要刷新**；三条各带不同的事实摘句（本轮 E4 / E5 / E1） |
| 页脚 | 写「诊断完成：72（推荐）｜事实清单 v1 · 5 条｜最该先练 E4（见右栏…）」 |
| 左栏空白 | 1440 宽下左栏（分数卡 + 维度明细）和右栏高度接近，没有大片空洞 |

**关键判定**：分数出来后再等 5 秒，「最该先练 3 条」有没有自己出现。**不出现 = 不过**（这是上一轮修掉的问题，本轮已验证正常）。

---

## 四、第 3 步：AI 面试（3 题，约 2 分钟）

**操作**：点「进入 AI 面试」→ 轮数选 **3** → 「开始面试」→ 每题用正常口语回答 2–4 句 → 回车发送。

**预期**：

| 检查点 | 预期结果 |
| --- | --- |
| 首题到达 | ≤ 25s（本轮约 16s），顶部出现「第 1 / 3 轮」 |
| 每题标注 | 都有「事实层追问 / 方法层追问」+ 事实编号（E1…E5） |
| **事实覆盖** | 三题的编号**不能全是同一个**（本轮 E5 → E1 → E2） |
| 轮次推进 | 答完第 1 题约 10–15s 后变「第 2 / 3 轮」，前端不卡住 |
| 每题点评 | 回答后有一句点评 + 下一题，不会只有点评没有下一题 |
| 答满 3 轮 | 顶部变「**已答完 3 / 3 轮**」；输入框变灰、发送按钮变灰；占位文字「计划 3 轮已答完，点右上「结束本场」看复盘」 |
| 服务端落库 | 开 F12 → Network 看 `/interview/answer` 都 200；或直接看复盘是不是 3 题 |

> 如果第 3 题答完仍能继续输入并发送 → 不过（上一轮修掉的问题）。
> 如果题目编号三题都是 E1 → 不过（本轮已修，`asked_facts` 应为三条不同）。

---

## 五、第 4 步：复盘（约 30 秒）

**操作**：点右上「结束本场」→ 弹窗「按已答的 3 题生成复盘，并结束这一场？」→ 点「生成复盘」。

**预期**：

| 检查点 | 预期结果 |
| --- | --- |
| 弹窗文案 | 明确写「按已答的 **3** 题」 |
| 生成耗时 | ≤ 60s（本轮 30s）；期间有「生成中」提示，页面不假死 |
| 自动跳转 | 到时间自己切到复盘页，**不需要刷新** |
| 标题 | 「专业面 · 3 轮问答 · 岗位「后端开发工程师 · 上海」」 |
| 逐题卡 | **正好 3 张**，编号 01/02/03，与问过的题一一对应 |
| 每卡三栏 | 想验证 / 本可以答成 / 差在哪 —— **三栏内容必须不同**（不能同一句复制三遍） |
| STAR | 四字母有高亮（on 绿）与划掉（off 灰）区分，且**不要三题完全一致** |
| 卡点清单 | 3 条，每条都带「补一句什么话」的具体建议 |
| 分数 | 一个总分 + 五维；五维**不应该全同分** |

> 最容易判错的两点：① 复盘只有 2 题 → 落库丢题；② 五维全 7 → 区分度问题（本轮又出现）。

**预期**：

| 检查点 | 预期结果 |
| --- | --- |
| 文件 | 下载到「下载」目录，文件名 = 姓名.docx |
| 段落数 | 12–16 段（本轮 15 段） |

| 实习 | 抬头是「某电商公司 · 后端开发实习生 · 2022.07-2022.12」，**没有单独的 `- 2022.12 某电商公司` 行** |
| 技能 | `Java、Spring Boot、MySQL、Redis、Git`，**Spring Boot 不能被逗号拆开** |
| 用 Word 打开 | 不报「文件损坏」，字体、加粗、分隔线正常 |

## 七、第 6 步：窄屏（3 分钟，手机或 F12 设备模拟）

**操作**：F12 → 切设备模拟，依次选 320 / 360 / 390 / 414 宽，看编辑页和复盘页。

**预期**：

| 宽度 | 预期 |
| --- | --- |
| 360 / 390 / 414 | 完全无横向滚动条；要点输入框文字换行完整、不截断；工具栏三个按钮分行排列不挤压 |
| 320 | 无横向滚动条，但「+ 添加技能 / 添加证书」按钮**右侧会被裁掉约 10px**（本轮发现，属已知问题） |
| 复盘页 | 卡片头部是「标题 → 结论小字 → STAR 标签」三行，标签不挤在标题后面 |

判断有没有横向溢出：F12 控制台执行
`document.documentElement.scrollWidth === document.documentElement.clientWidth`，应返回 `true`。

## 九、这几个别当成 bug（已知误报）

| 现象 | 真相 |
| --- | --- |
| 鼠标点「Send answer」没反应 | 测试工具的悬浮球压在按钮上；用回车发送或刷新就好 |
| 点「结束本场」提示被遮罩盖住 | 应用用的是自绘确认框，遮罩属正常 |
| 页面突然所有操作都超时、但标签还在、标题正常 | 已知的框架级僵死（累计 3 次），关标签重开即可，`localStorage` 里的进度不会丢 |
| 诊断分数每次不一样（63 / 70 / 72） | 模型输出，波动 5–10 分属正常；但五维全同分不正常 |

## 十、本轮已知问题速查（跑的时候大概率会撞到）

| 位置 | 现象 |
| --- | --- |
| 粘贴解析 | 实习公司变 `2022.07`、多出垃圾要点、教育日期重复 |
| 技能 | `Spring Boot` 被拆成 `Spring` + `Boot`；刚解析完计数显示 0 |
| 面试首题 | 可能会问「这段实习在哪家公司」——因为解析出来的事实是残的 |
| 复盘评分 | 五维可能全 7，三题 STAR 完全一致 |
| 导出 DOCX | 会带着上面那些解析残留一起进文件 |
| 320 宽 | 「添加技能」按钮被裁 |
