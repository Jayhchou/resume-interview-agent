# 分享链接 · 用户视角测试教程

> 用途：把链接发给别人之前，先自己当一次「完全不懂这个项目的陌生人」，判断他用不用得下去。
> 链接：`https://resume-coach-22171.app.workbuddy.host/?sharecode=B4EIHAJGEK`
> 原则：**不解释、不指导、不帮他想**。你就是收到链接的人，只会点、看、判断。
>
> **前提：收链接的人什么都不用装、什么都不用填。** 不注册、不登录、不输密钥、不选模型。
> 如果他需要做其中任何一件，就已经不算「点开即用」了 —— 直接记为不通过。

---

## 0. 把自己变成「陌生人」（2 分钟）

这一节只做一件事：**让这台设备看起来像第一次打开这个链接**。不做任何技术操作。

| 步骤 | 怎么做 | 为什么 |
| --- | --- | --- |
| 1 | 在电脑上换一个**从没打开过这个链接的浏览器**（Edge / Chrome / 火狐任选），或用无痕窗口 | 别人手里就是一台普通电脑，不是你调过的工作机 |
| 2 | 把链接**先发到微信/QQ，再从聊天窗口点开** | 真实转发就是这一步：链接被截断、参数丢失只在这时暴露 |
| 3 | 手边放个秒表（手机计时器即可） | 后面每一步都要计时，卡不卡是主观感受，秒数是证据 |
| 4 | 最好再找**一个没听过这个项目的人**跑一遍，你只观察不提示 | 你会发现所有你以为「显然」的地方都不显然 |

> 不做任何技术操作：不开 F12、不清缓存、不改设置、不装任何东西。
> **要开开发者工具才能用得顺，本身就是问题。**
>
> 本教程只覆盖**网页端**（电脑浏览器打开链接）。分享出去的产品形态就是这一个网页，没有客户端、没有小程序，所以不必测手机。

## 1. 打开链接：前 5 秒（计时）

**你要判断的只有一个问题：这是干什么的？**

| 观察点 | 期望 | 不通过长什么样 |
| --- | --- | --- |
| 打开耗时 | ≤ 3s 出现内容 | 白屏、一直转圈 |
| 首屏有没有一句话说清用途 | 能读到类似「诊断简历 + 模拟面试」 | 只看到「选一个模板，开始制作」→ 像简历排版工具 |
| 有没有登录/授权/填手机号 | 不需要 | 任何拦在门口的注册墙 |
| 有没有「演示 / Demo / 内测」字样 | 没有 | 看到「演示不会真的上传」，你会立刻不想给真简历 |
| 下一步是否明确 | 一眼知道该点哪儿 | 三个模板并列但不知道区别 |

**判定**：遮住页面，问自己「这东西能帮我干什么」。答不上来 = 首屏失败。

---

## 2. 交简历：上传 or 粘贴（2 分钟）

**操作**：先试着点「点击选择文件」选一份真 PDF/Word；不行再展开「或者粘贴简历文本」。

| 观察点 | 期望 | 不通过 |
| --- | --- | --- |
| 上传是否真的读到了内容 | 选完文件后 3s 内进入编辑器，姓名/学校/公司都在 | 提示「演示不会真的上传」、或毫无反应 |
| 解析准确性 | 公司名 = 公司、岗位 = 岗位、时间段 = 时间段、要点条数对得上 | 公司名变成 `2022.07`、凭空多出一条 `- 2022.12 某电商公司` |
| 技能 | `Spring Boot` 是一个整体 | 被拆成 `Spring` 和 `Boot` 两个 |
| 教育 | 入学—毕业时间只出现一次 | 同一行里出现两遍日期 |
| 左侧模块计数 | 「6 项技能」与实际一致 | 显示「0 项技能」 |
| 能不能改 | 每一格都能点进去改 | 只能看不能改 |

**判定**：解析错的每一处，后面都会变成面试问题。**解析错 = 全链路错**。

---

## 3. 诊断：等多久、给的东西有没有用（2 分钟）

**操作**：点「五维图分析」，开始计时，**中途不要刷新**。

| 观察点 | 期望 | 不通过 |
| --- | --- | --- |
| 出分耗时 | ≤ 40s | 60s 以上，或永远「分析中」 |
| 等待期间有反馈 | 有阶段提示（找证据 → 建事实清单 → 出分） | 只有骨架屏转圈、分数固定 0 |
| 空简历时的行为 | 直接提示「先填简历」，不让跑 | 跑起来卡住，总分 0，AI 让你「把简历贴过来」 |
| 五个维度 | **不全相同**，能看出强弱项 | 5 个都是 7，雷达图是正五边形 |
| 扣分理由 | 每条引用你简历原文 + 说清为什么扣 | 只有泛泛而谈的套话 |
| 「最该先改三件事」 | 有 3 条具体内容 | 只有一张「改完这几处…」的空卡 |
| 分数可信度 | 与你自评差不太多 | 明显离谱（比如全空也给 70+） |

**判定**：诊断的意义是「告诉你先改哪三处」。三件事是空的 = 这次诊断没产出。

---

## 4. 面试：能不能连下去（5 分钟）

**操作**：点「进入 AI 面试」→ 轮数选 3 → 开始 → 每题用口语答 2–4 句 → 回车发送。

| 观察点 | 期望 | 不通过 |
| --- | --- | --- |
| 首题到达 | ≤ 25s | 30s 无题、页面空白 |
| 题目是否来自你的简历 | 引用你的项目/实习，带编号 E1… | 通用八股题 |
| 编号是否发散 | 三题覆盖不同经历（E1/E2/E3…） | 三题全问同一条 |
| **轮次是否推进** | 顶部「第 1 / 3」→「第 2 / 3」→「第 3 / 3」 | 答完仍是「第 1 / 3」 |
| 答完能不能发下一题 | 每题都正常出下一题 | 卡住、需要刷新 |
| 答满 3 轮 | 输入框和发送按钮变灰，提示「已答完」 | 还能继续发 |
| 回答有没有被记住 | 后面的题会引用你上一题的说法 | 每题都像第一次见你 |

**判定**：轮次计数器不动 = 回答没存进去。这一条不过，后面复盘一定是空的。

---

## 5. 复盘：花钱买的就是这一步（3 分钟）

**操作**：点「结束本场」→ 若有确认框，点「生成复盘」→ 计时，**不要刷新**。

| 观察点 | 期望 | 不通过 |
| --- | --- | --- |
| 结束时有确认 | 弹窗写「按已答的 3 题生成复盘」 | 直接跳走、没有任何提示 |
| 生成耗时 | ≤ 60s，期间有进度 | 一直「生成中」、页面假死 |
| 是否自动跳转 | 自己切到复盘页 | 必须手动刷新才出现 |
| 题目条数 | **等于你答的题数**（3 题就 3 张卡） | 少题、或 4 张卡 |
| 每卡内容 | 想验证 / 本可以答成 / 差在哪 **三栏不同** | 同一句话复制三遍 |
| STAR | 有高亮和划掉的区别，且三题不完全一样 | 三题完全雷同 |
| 卡点建议 | 每条都告诉你「补哪一句」 | 只写「缺数据」不写怎么补 |
| 分数 | 一个总分 + 五维，五维有差异 | 五维全同分 |

**判定**：如果点「结束本场」后回到的是「选择面试场景」，说明整场面试被丢弃了 —— 这是最严重的一类失败。

---

## 6. 结果能不能带走（1 分钟）

| 观察点 | 期望 | 不通过 |
| --- | --- | --- |
| 有没有「导出」入口 | 编辑页能找到「导出 DOCX」 | 根本没有这个按钮 |
| 导出的文件 | 用 Word 能打开，姓名/教育/实习/项目/技能齐全 | 打不开、缺段、日期重复、技能被拆开 |
| 改完再导出 | 反映最新修改 | 还是旧内容 |

---

## 7. 刷新与回访（30 秒）

| 观察点 | 期望 | 不通过 |
| --- | --- | --- |
| 打开链接 | 直接回到上次进度 | 回到「选一个模板」，像全丢了 |
| 刷新页面 | 停在当前页 | 跳回首页 |

## 8. 打分表（9 项，每项 0/1/2 分，满分 18）

| # | 项目 | 2 分 | 1 分 | 0 分 |
| --- | --- | --- | --- | --- |
| 1 | 首屏说清用途 | 5 秒能说出用途 | 要摸索 | 以为是别的工具 |
| 2 | 交简历顺畅 | 上传即用 | 只能粘贴 | 都走不通 |
| 3 | 解析准确 | 全对 | 小错 | 公司/时间错位 |
| 4 | 诊断速度 | ≤40s | 40–70s | >70s 或卡死 |
| 5 | 诊断有用 | 3 条具体建议 | 建议笼统 | 三条为空 |
| 6 | 面试可连 | 轮次正常推进 | 偶发卡顿 | 计数不动 |
| 7 | 复盘完整 | 题数对、三栏不同 | 少题 | 没有复盘 |
| 8 | 结果可带走 | 导出正常 | 导出有瑕疵 | 没有导出 |
| 9 | 刷新与回访 | 回到原处 | 需重新进入 | 全丢 |

- **≥14 分**：可以发给真人
- **10–13 分**：能演示，别当产品发
- **<10 分**：先别发，别人会在第一分钟就走

## 9. 每条不通过怎么记（照抄这个格式）

```
【步骤】第 4 步 面试 · 第 2 题
【我做了什么】答完第 1 题，等 40 秒
【我看到什么】顶部仍显示「第 1 / 3 轮」，下一题已出现
【我预期】变成「第 2 / 3 轮」
【影响】不知道还要答几题；结束时复盘是空的
【证据】截图 + 时间
```

## 附：本次实测基线（2026-11-09 重新发布后，网页端）

线上版本：`app.js?v=39` / 115KB、`agent.js?v=22`，后端 `/api/health` 200。以下每条都是刚跑出来的，不是推断。

| 步骤 | 实测结果 | 判定 |
| --- | --- | --- |
| 1 打开链接 | 0.3s 出内容，无登录/注册/填密钥 | 通过 |
| 1 首屏文案 | 主标题仍是「选一个模板，开始制作」 | **不通过**：像排版工具 |
| 2 交简历 | 粘贴即解析，进入编辑器 | 通过（上传未验） |
| 2 解析准确 | 公司、时间、技能、条数全对，`Spring Boot` 未被拆 | 通过 |
| 3 诊断速度 | **18s** 出 75 分 | 通过 |
| 3 诊断内容 | 5 条原文证据 + 改法；「最该先改的三件事」卡片仍空 | 部分不通过 |
| 4 面试 | 首题 10s 到，锚定 E2；三题覆盖 E2/E4/E1；轮次 1/3→2/3→3/3 | 通过 |
| 4 答满 | 「已答完 3 / 3 轮」，输入与发送锁死 | 通过 |
| 5 复盘 | 确认框正常；点「生成复盘」后 **130s 无结果**，服务端 `has_report=false`、`stage=S0` | **不通过** |
| 6 导出 | `林可 (6).docx` 37KB，姓名/教育/实习/项目/技能齐全 | 通过 |
| 7 刷新 | **回到「选一个模板」**，且命中旧版缓存会把简历覆盖成空 | **不通过（最严重）** |

**本次打分：11 / 18**（1+1+2+2+1+2+0+2+0）

> 结论：单次「不刷新、一路走到底」的体验已经能打通诊断、面试、导出；但**只要刷新一次，就会掉进旧版缓存并丢掉简历**，而复盘这一步目前拿不到。按第 8 节阈值（10–13 分）= 能演示，别当产品发。
