# 03 · 逻辑梳理

> 本文回答：一次完整交互内部到底怎么跑、在哪些地方会断、断了怎么办。

---

## 一、设计原则

1. **一次只做一件事。** 不要在一个回合里同时要求解析、诊断、改写。分步输出的质量远高于一次问全。
2. **结论必须可定位。** 任何评价都要能指回原文的具体片段，不指不出口。
3. **不编造事实。** 改写只在表达层动手，事实层冻结。
4. **追问要有依据。** 下一问必须从上一答里最薄的那一层长出来，不是从题库里抽。

---

## 二、主流程状态机

```
        ┌──────────┐
        │  进入    │
        └────┬─────┘
             ↓
      ┌──────────────┐
      │ 意图识别     │  三个出口：诊断 / 改写 / 面试
      └──┬────┬───┬──┘
         │    │   │
    ┌────↓┐ ┌↓───┐ ┌↓────────┐
    │简历流│ │改写│ │面试流    │
    └──┬──┘ └┬───┘ └┬────────┘
       │     │      │
       └──┬──┘      │
          ↓         ↓
     ┌────────┐ ┌────────┐
     │诊断报告│ │复盘报告│
     └───┬────┘ └───┬────┘
         └────┬─────┘
              ↓
        ┌───────────┐
        │ 下一步建议 │  → 回到任意流（闭环）
        └───────────┘
```

> 注意：简历流除了输出诊断报告，还必须产出**候选人事实清单**（见第四节）——它是面试流的唯一输入。图上两条线不是断的，接口在第四节。

### 2.1 意图识别规则

| 用户说法 | 判定 | 说明 |
|---|---|---|
| 「帮我看看简历」 | 简历流 | 无岗位信息 → 先问岗位，或降级通用诊断 |
| 「投这个岗位怎么改」 | 改写流 | 需 JD，缺失则先要 JD |
| 「模拟面试」「练一下」 | 面试流 | 需岗位 + 简历（简历可选） |
| 只说「你好」/ 含糊 | 引导 | 给三个入口让他选，不猜 |

**关键点：宁可多问一句，不要猜错方向。** 猜错的代价是用户拿走了错误的诊断，比多一轮对话严重得多。

## 三、简历流

### 3.1 步骤拆解

| 步 | 动作 | 输出 | 中断条件 |
|---|---|---|---|
| 1 | 收集材料 | 简历文本 + 目标岗位 | 简历是图片 → 请求转文本 |
| 2 | 结构化解析 | 教育 / 经历 / 项目 / 技能 | 字段大量缺失 → 提示补充 |
| 3 | 岗位匹配分析 | 关键词覆盖率、缺口清单 | 无 JD → 跳过，转通用诊断 |
| 4 | 五维诊断 | 分项分 + 逐条扣分理由 + 原文定位 | — |
| 5 | 改写建议 | 对照表：原句 → 建议 → 理由 | 仅对用户指定的条目做 |

### 3.2 五维诊断的评分口径

| 维度 | 权重 | 判断依据 | 典型扣分点 |
|---|---|---|---|
| 岗位匹配 | 25% | 与 JD 关键词的重合度**与出现位置** | 关键技能只在末尾「技能清单」出现，经历里没有呼应 |
| 证据强度 | 30% | 是否用数字 / 规模 / 结果描述产出；角色是否可辨 | 「负责运营公众号」——多少阅读？多少增长？ |
| 结构清晰 | 15% | 时间倒序、条目平行、一行一果 | 混用「负责 / 参与 / 协助」导致责任边界模糊 |
| 表达精炼 | 15% | 形容词密度、空话比例 | 「认真负责、积极主动、抗压能力强」连用 |
| 差异化亮点 | 15% | 同类候选人里能否被记住；有无可复述的具体事件 | 通篇与岗位无关的通用经历，没有一件能讲成故事 |

**输出要求**：每一处扣分必须带 `原文片段` + `问题类型` + `修改方向`，三者缺一不可。五维分为雷达图，可直接截图用于演示前后对比。

> 权重会随场景微调：投技术岗时「岗位匹配」上调、「差异化」下调；投管培生时反之。默认权重即上表。


### 3.3 改写的事实冻结规则

改写时按住四类实体不动：**时间、组织名称、职位名称、数字**。

- 允许：把「负责用户增长」改成「主导新用户拉新，3 个月内新增注册 2.1 万」
  —— 前提是原文已有「2.1 万」这个数字，否则属于编造。
- 禁止：原文没有数字，却在改写里补一个。

没有数字怎么办？**不给数字，给提问**：「这段经历里，你能回忆起任何可量化结果吗？比如覆盖人数、频率、时长、金额。」——把缺证据变成一次对话，而不是替他填。

## 四、模块交接：候选人事实清单

> 这是两个技能之间**唯一的接口**。`resume-coach` 产出它，`interview-coach` 只读它。
>
> 不靠会话记忆衔接——记忆会漂移、会串味、换个会话就没了；文件不会。

### 4.1 为什么必须要它

| 若不做清单 | 后果 |
|---|---|
| 面试技能直接读简历原文 | 简历里全是形容词，没有可定位的结构；模型只能凭印象出题，每道题都问不出「为什么问这个」 |
| 靠会话上下文传递 | 一个会话跑完诊断 + 二十轮面试，后半段开始忘；且从「耐心改写」切到「施压追问」会串味 |
| 让学生自己复述 | 信息在转述中被美化，正好丢掉最该被追问的部分 |

### 4.2 字段定义（每条经历一条记录）

| # | 字段 | 必填 | 内容规则 | 面试侧用途 |
|---|---|---|---|---|
| 1 | `id` | ✅ | E1、E2 顺序编号，**全生命周期不变** | 复盘按 id 定位到题，做到「问题可溯源」 |
| 2 | `事实句` | ✅ | 一句话压缩「在哪 / 做了什么 / 用什么方法」，**不含形容词** | 行为面的题干 |
| 3 | `结果` | ✅ | 必须带数字或可验证事实；缺则写 `【待核实】`，**禁止推测补全** | 追问的第一刀；`【待核实】` 是最高优先级追问点 |
| 4 | `角色` | ✅ | 只能填：主导 / 参与 / 协助 / 独立 | 归因层追问（「这部分到底是你做的还是团队做的」） |
| 5 | `证据强度` | ✅ | 强 / 中 / 虚，由 `结果` + `角色` 判定 | 决定提问顺序：**虚的排前面** |
| 6 | `追问链` | ⭕ | 预设 2–3 层下潜问法 | 追问的备用轨道，防止现场跑偏 |

### 4.3 清单级信息（整份一份）

- 目标岗位（可多个，分别标注）
- 五维分数（含分项，见 3.2）
- 前三大证据缺口（按优先级排序）
- 清单版本号：`v1` / `v2`…（分数变化即演示时的价值证明）

### 4.4 三条硬规则

1. **只写可核实项。** 清单里不出现建议、形容词、改写稿。它是病历，不是处方——处方在改写层。
2. **面试只能对清单条目提问**，每题必须标 `id`。禁止凭印象编问题，这是「模拟面试官瞎问」的唯一解药。
3. **答不上来的点回填为新的证据缺口**，在下一轮简历改写时优先处理。闭环靠这一条才成立。

### 4.5 输出模板

`resume-coach` 在诊断完成后**自动**产出（不需要用户额外要求），存为工作区文件 `candidate-fact-sheet.md`：

```
清单版本：v1 ｜ 目标岗位：产品经理（互联网）
五维分数：岗位匹配 62 / 证据强度 45 / 结构清晰 70 / 表达精炼 55 / 差异化 40

| id | 事实句 | 结果 | 角色 | 证据强度 | 追问链 |
|----|--------|------|------|----------|--------|
| E1 | 校园二手交易平台，负责后端下单接口 | 【待核实】 | 参与 | 虚 | 1. 日均调用量？ 2. 你写了哪几个接口？ 3. 遇到并发问题了吗 |
| E2 | 社团招新，设计并执行线上宣传 | 报名 320 人，同比 +45% | 主导 | 强 | 1. 45% 怎么统计的 2. 各渠道占比 3. 明年会改什么 |

证据缺口（优先级从高到低）：
1. E1 缺全部量化 —— 面试必问
2. E2 结果可信但过程缺失 —— 追问方法与渠道
3. 全篇无差异化亮点 —— 需补一件「只有你做过」的事
```

**存放与脱敏**：同一求职周期内复用；换岗位时新建一份并递增版本号；清单内不写入任何真实姓名、电话、院校。

## 五、面试流


### 5.1 追问策略（核心机制）

这是本项目与「通用模型随便问几句」的核心差异。追问遵循**逐层下潜**模型：

```
第 1 层：事实      「你在那个项目里具体做了什么？」
第 2 层：方法      「你用什么方法做的？为什么选这个方法？」
第 3 层：量化      「结果如何衡量？提升了多少？」
第 4 层：归因      「提升主要来自你的哪一部分工作？」
第 5 层：反思      「如果重做一次，你会改哪里？」
```

**下潜规则：**

1. 每轮只问一个问题。
2. 下一层的问题必须引用上一答中的**具体词句**，证明在听。
3. 当某一层回答出现以下信号时，**不往下潜，就地深挖**：
   - 只有形容词没有动作（「我负责统筹」）
   - 只有团队没有个人（「我们完成了」）
   - 只有结果没有过程（「最后效果很好」）
4. 连续两轮在同一层打转，说明用户储备不足 → 停止追问，给出示范答法，再重问一次。

### 5.2 面试场景与确认流程

**场景必须由学生显式选择，不让模型从简历里推断。** 同一份简历可以投产品岗也可以投运营岗，猜错的代价是整场面试白跑。

开场先确认三项，缺哪项问哪项，**三项未齐不得开始提问**：

1. 场景：综合面 / 专业面 / 压力面
2. 目标岗位
3. 轮次：一面 / 二面 / 终面

| 场景 | 出题依据 | 追问重点 | 层数上限 | 对数字的态度 |
|---|---|---|---|---|
| 综合面 | 简历经历 + 求职动机 | 归因、反思、稳定性 | 3 | 温和确认 |
| 专业面 | JD 硬性要求 + 项目细节 | 方法、边界、取舍 | 3 | 追问依据与来源 |
| 压力面 | 清单里最虚的条目 | 反复追问同一缺口 | 4+ | 直接质疑「这算你的功劳吗」 |

⚠️ **三种场景若只在题库上不同，等于一张皮。** 必须在「层数上限 / 是否质疑 / 复盘权重」三处同时体现差异，否则录屏里看起来完全一样。具体数值等第一轮跑通后再定（半可逆项）。

### 5.3 复盘报告结构

| 模块 | 内容 |
|---|---|
| 总体结论 | 一句话：能过 / 悬 / 明显不足，并给理由 |
| 逐题诊断 | 每题标注最薄弱的一层（如「第 3 层缺量化」） |
| 表达问题 | 冗长、跑题、被动语态、口头语过多 |
| 结构问题 | 没有「情境—任务—行动—结果」的骨架 |
| 改进动作 | 3 条以内，每条具体到「下次这样说：……」 |
| 推荐练习 | 指向下一轮该练什么 |

**禁止**：只写「表达流畅」「逻辑清晰」这类结论。每条评价后面必须跟一个可执行动作。

## 六、边界与拒答

### 6.1 三类必须拒绝的请求

| 请求 | 判定 | 应对话术方向 |
|---|---|---|
| 「帮我编一段实习经历」 | 事实虚构 | 说明风险：背调与追问都会露；转为「把你真实做过的事写到最好」 |
| 「把这个项目写成我主导的」 | 归因夸大 | 区分「参与」与「主导」的证据差异；建议如实标注贡献边界 |
| 「面试时问到不会的怎么撒谎」 | 诚信风险 | 给真实可行的应对框架：承认边界 + 迁移能力 + 学习计划 |

**这三条不是技术限制，是产品底线。** 答辩时这会是加分项——它证明团队想过「这东西被用坏了会怎样」。

### 6.2 能力边界（做不到就直说）

- 无法核实简历真实性（无数据源）
- 无法解析扫描件与图片简历
- 无法替代真实 HR 的岗位判断（只能做通用匹配）
- 无法保证面试通过（只提升表达与结构）

## 七、提示词分层

| 层 | 位置 | 内容 | 谁维护 |
|---|---|---|---|
| 系统层 | 专家人设与提示词 | 身份、总体工作流、输出风格、拒答规则 | 托管人 |
| 技能层 | 各 `SKILL.md` | 单一能力的执行步骤与输出契约 | 各角色 |
| 任务层 | 用户当次输入 | 具体简历、JD、回答 | 用户 |

**分层纪律：** 不要在技能层重复写人设，也不要把技能步骤塞进系统层。混层会让提示词越改越乱，且无法定位问题出在哪一层。

---

## 八、失败模式与兜底

| 失败模式 | 表现 | 兜底策略 |
|---|---|---|
| 输出泛化 | 全是「建议突出亮点」这类空话 | 强制输出模板：每条必须带原文片段与修改方向 |
| 编造数字 | 改写中出现原文没有的量化结果 | 改写前后做实体比对，数字只减不增 |
| 追问退化 | 连着几轮问同一层 | 计数：同层两轮即切换策略 |
| 过度美化 | 用词华丽但更空 | 约束「替换词必须是可被追问的具体表达」 |
| 上下文丢失 | 长对话后忘了岗位 | 每轮开头复述岗位卡关键字段 |
| 用户材料不全 | 没 JD / 没简历 | 降级模式：通用诊断 + 明确告知局限 |
