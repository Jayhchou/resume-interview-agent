# 03 · 逻辑梳理

> 本文回答：一次完整交互内部到底怎么跑、在哪些地方会断、断了怎么办。
> 评分口径、字段定义以本文为准，代码实现不得自行扩展。

---

## 一、设计原则

1. **一次只做一件事。** 不在一个回合里同时要求解析、诊断、改写。分步输出的质量远高于一次问全。
2. **结论必须可定位。** 任何评价都要能指回原文的具体片段，不指不出口。
3. **不编造事实。** 改写只在表达层动手，事实层冻结。
4. **追问要有依据。** 下一问必须从上一答里最薄的那一层长出来，不是从题库里抽。
5. **能算的不要让模型猜。** 分数、匹配度、卡点回写全部可人工复算，模型只负责解释理由。

---

## 二、主流程状态机

```
        ┌──────────────┐
        │  S0 空载     │  无简历
        └──────┬───────┘
               │ 上传 / 录入 / 解析成功
               ↓
        ┌──────────────┐
        │  S1 已解析   │  五类字段就绪，可指令改稿
        └──────┬───────┘
               │ 选定目标岗位并锁定 JD
               ↓
        ┌──────────────┐
        │  S2 已诊断   │  五维分数 + 逐条问题 + 四联改写
        └──────┬───────┘
               │ 自动抽取（无需用户额外要求）
               ↓
        ┌──────────────┐
        │  S3 已建清单 │  事实清单 v1（可编辑、可升版本）
        └──────┬───────┘
               │ 开场三确认通过
               ↓
        ┌──────────────┐
        │  S4 面试中   │  逐题单问、沿五层下潜
        └──────┬───────┘
               │ 达轮次上限或学生主动结束
               ↓
        ┌──────────────┐
        │  S5 已复盘   │  JSON 报告 + 卡点清单
        └──────┬───────┘
               │ 卡点回写清单 → 升版本
               └──────────▶ 回到 S2（二次训练）
```

**状态即权限**：S1 之前不得进诊断（五类字段有空项时只列缺项、不出分）；S3 之前不得进面试（事实清单为空时先索要，不直接出题）。

### 2.1 模块切换靠区块，不靠模型猜

上一版设计让模型做意图识别（「帮我看看简历」→ 诊断流）。改为 Web 应用后，**模块由三块页面所在位置决定**，模型不再负责判断「用户想干什么」。

| 旧做法 | 现做法 | 收益 |
|---|---|---|
| 模型从一句话里推断意图 | 用户点工作区 / 对话区 / 报告区 | 猜错方向的代价归零 |
| 含糊输入要反问 | 界面本身就是入口 | 首轮对话成功率 100% |

**唯一仍需解析的是改稿指令**——因为「改第二条」「把项目移到教育前面」是自然语言。

### 2.2 改稿指令解析规则

| 指令形态 | 例 | 解析结果 |
|---|---|---|
| 定点改写 | 「第二条经历补上并发优化的结果」 | 定位 `经历[2]` → 改写该条 → 回显完整稿件 |
| 顺序调整 | 「把项目移到教育前面」 | 交换区块顺序 → 回显 |
| 增 / 删 | 「删掉第三段项目」 | 删除 `项目[3]` → 回显 |
| 回退 | 「回到上一版」 | 读取上一版本快照 → 回显 |

**铁律：每次执行后必须回显完整稿件。** 只回显被改的那一句，学生无法确认上下文有没有被连带破坏。改错必须可指令回退。

## 三、简历流

### 3.1 五类字段

| # | 字段 | 内容 | 解析要求 |
|---|---|---|---|
| 1 | 基本信息 | 姓名以外的可公开项，联系方式不强制 | 不采集手机号、院校（见第六节） |
| 2 | 教育 | 学历、专业、时间 | 时间格式统一，倒序 |
| 3 | 经历 | 实习 / 工作，含事实句与结果 | 每条必须可独立成句 |
| 4 | 项目 | 项目名、角色、方法与结果 | 同上 |
| 5 | 技能 | 技能栈、证书 | 与岗位要求做交集匹配 |

五类字段**全空时不得进入诊断**。上传稿与空白新建稿走同一套字段结构，同一套指令都适用——这一点不平权，后面所有诊断都会失真。

### 3.2 五维诊断口径

> 这是**职业能力五维**，用于简历诊断。另有**面试能力五维**用于复盘，两者是两套，不合并、不互相换算（见 5.4）。

| 维度 | 权重 | 评估依据（取自简历原文） | 典型扣分点 |
|---|---|---|---|
| **专业基础** | 20% | 课程、证书、技能栈与目标岗位要求的重合度 | 关键技能只在末尾「技能清单」出现，经历里没有任何呼应 |
| **实践经历** | 30% | 实习、项目、竞赛的时长、真实性与覆盖面 | 全是课程作业，没有真实场景与他人协作 |
| **成果产出** | 20% | 结果是否有数字或可验证物，与角色是否匹配 | 「负责运营公众号」——多少阅读？多少增长？ |
| **沟通表达** | 15% | 句子是否讲清动作与对象，条目能否快速扫读 | 「认真负责、积极主动、抗压能力强」连用 |
| **协作推进** | 15% | 经历与项目条目中标注的角色（主导 / 参与 / 协助 / 独立）与协作规模（团队人数、跨部门数），取自简历原文措辞 | 通篇都是「参与」，没有一件能说清自己主导了什么 |

**输出要求**：每一处扣分必须带 `原文片段` + `问题类型` + `修改方向`，三者缺一不可。只给总分视为不可解释。

**权重不可配置**。五维各为 1–10 分整数，键名见 [`01-需求分析.md`](01-需求分析.md) 附录 A.5。同一稿件连跑两次，各维波动 ≤1 分、总分波动 ≤5 分。

### 3.3 岗位匹配度如何计入

**岗位匹配度不是第六维，也不单独出分**——2.2 的五维表里没有它，它只作为「专业基础」的算分输入。

```
取会话内已锁定的 JD 技能要求集合 A
取简历技能栈集合 B
重合率 r = |A ∩ B| / |A|
按 01 附录 A.5 的映射表把 r 折成 1-10 分，作为 foundation 维的分数
```

- 映射表由后端写死，模型不得自行改判「像不像」
- JD 在诊断开始时抽成五字段后**锁存**，当次会话不再变更
- 诊断、出题、复盘全程共用同一份，不因二次检索而改变
- 检索失败回落岗位基线库 `job-catalog.md`，不得中断

### 3.4 定向改写的四联对照

指定任一低分句（引原句或说第几条），输出四栏：

| 栏位 | 内容 | 缺一即不合格 |
|---|---|---|
| 原句 | 原文原样引用 | — |
| 问题诊断 | 属于哪一维、扣在哪 | — |
| 改写示例 | 只改表达，不动事实 | — |
| 需你补充的信息 | 无法改写时给提示，不硬编 | — |

每条必须附一句**为何这样改**。只给结果不达标。

### 3.5 改写的事实冻结规则

改写时按住四类实体不动：**时间、组织名称、职位名称、数字**。

- 允许：把「负责用户增长」改成「主导新用户拉新，3 个月内新增注册 2.1 万」
  —— 前提是原文已有「2.1 万」这个数字，否则属于编造。
- 禁止：原文没有数字，却在改写里补一个。

没有数字怎么办？**不给数字，给提问**：「这段经历里，你能回忆起任何可量化结果吗？比如覆盖人数、频率、时长、金额。」——把缺证据变成一次对话，而不是替他填。

## 四、模块交接：事实清单

> 这是诊断与面试之间**唯一的接口**。诊断产出它，面试只读它。
> 不靠会话记忆衔接——记忆会漂移、会串味、换个会话就没了；结构化的清单不会。

### 4.1 为什么必须要它

| 若不做清单 | 后果 |
|---|---|
| 面试直接读简历原文 | 简历里全是形容词，没有可定位的结构；模型只能凭印象出题，每道题都问不出「为什么问这个」 |
| 靠会话上下文传递 | 会话跑完诊断 + 二十轮面试后开始遗忘；且口吻从「耐心改写」切到「施压追问」会串味 |
| 让学生自己复述 | 信息在转述中被美化，正好丢掉最该被追问的部分 |

### 4.2 六字段（每条经历一条记录）

| # | 字段 | 必填 | 内容规则 | 面试侧用途 |
|---|---|---|---|---|
| 1 | `id` | ✅ | E1、E2 顺序编号，**全生命周期不变** | 复盘按 id 定位到题，做到「问题可溯源」 |
| 2 | `事实句` | ✅ | 一句话压缩「在哪 / 做了什么 / 用什么方法」，**不含形容词** | 行为面的题干 |
| 3 | `结果` | ✅ | 必须带数字或可验证事实；缺则写 `【待核实】`，**禁止推测补全** | 追问的第一刀；`【待核实】` 是最高优先级追问点 |
| 4 | `角色` | ✅ | 只能填：主导 / 参与 / 协助 / 独立 | 归因层追问（「这部分到底是你做的还是团队做的」） |
| 5 | `证据强度` | ✅ | 强 / 中 / 虚，由 `结果` + `角色` 判定 | 决定提问顺序：**虚的排前面** |
| 6 | `追问链` | ⭕ | 预设 2–3 层下潜问法 | 追问的备用轨道，防止现场跑偏 |

**字段顺序固定，任一必填项缺失即视为结构错误。**

### 4.3 清单级信息（整份一份）

- 目标岗位（可多个，分别标注）
- 职业能力五维分数（1–10 分整数，键名见 01 附录 A.5）
- 前三大证据缺口，字段名 `top_gaps`（按优先级排序）
- 清单版本号：`v1` / `v2`…（分数变化即演示时的价值证明）

### 4.4 三条硬规则

1. **只写可核实项。** 清单里不出现建议、形容词、改写稿。它是病历，不是处方——处方在改写层。
2. **面试只能对清单条目提问**，每题必须标 `id`。禁止凭印象编问题，这是「模拟面试官瞎问」的唯一解药。
3. **答不上来的点回填为新的证据缺口**，在下一轮简历改写时优先处理。闭环靠这一条才成立。

### 4.5 输出格式

服务端以 JSON 存于 session，同时可导出 Markdown 供学生留存：

```json
{
  "sheet_version": "v1",
  "target_roles": ["后端开发"],
  "resume_version": "V1",
  "scores": {
    "foundation": 6, "practice": 4, "output": 7,
    "expression": 5, "collaboration": 4
  },
  "items": [
    {
      "id": "E1",
      "fact": "校园二手交易平台，负责下单接口开发",
      "result": "【待核实】",
      "role": "参与",
      "strength": "虚",
      "follow_ups": ["日均调用量多少", "你写了哪几个接口", "遇到过并发问题吗"]
    },
    {
      "id": "E2",
      "fact": "社团招新，设计并执行线上宣传",
      "result": "报名 320 人，同比 +45%",
      "role": "主导",
      "strength": "强",
      "follow_ups": ["45% 怎么统计", "各渠道占比", "明年会改什么"]
    }
  ],
  "top_gaps": [
    {"priority": 1, "fact_id": "E1", "desc": "缺全部量化，面试必问"},
    {"priority": 2, "fact_id": "E2", "desc": "结果可信但过程缺失"},
    {"priority": 3, "fact_id": null, "desc": "全篇无差异化亮点"}
  ]
}
```

**两种缺口不共用字段名**：清单级（本节）叫 `top_gaps`，结构为 `{priority, fact_id, desc}`，回答「先补哪几条」；报告级（5.4、01 附录 A.1）叫 `gaps`，结构为 `{id, desc, fact_id, source, suggestion, status}`，回答「哪几条卡住了、补没补上」。两者不得混写。

**脱敏**：同一求职周期内复用；换岗位时新建一份并递增版本号；清单内不写入任何真实姓名、电话、院校。

## 五、面试流

### 5.1 开场三确认

**场景必须由学生显式选择，不让模型从简历里推断。** 同一份简历可以投产品岗也可以投运营岗，猜错的代价是整场面试白跑。

三项缺一，**不得进入答题**：

1. 场景：综合面 / 专业面 / 压力面
2. 目标岗位
3. 轮次：一面 / 二面 / 终面

### 5.2 追问五层模型

这是本项目与「通用模型随便问几句」的核心差异：

```
第 1 层 事实   「你在那个项目里具体做了什么？」
第 2 层 方法   「你用什么方法做的？为什么选这个方法？」
第 3 层 量化   「结果如何衡量？提升了多少？」
第 4 层 归因   「提升主要来自你的哪一部分工作？」
第 5 层 反思   「如果重做一次，你会改哪里？」
```

**下潜规则：**

1. **每轮只提一个问题。** 输出含两个及以上问号即判不合格，须回退重生成。
2. 下一层的问题必须引用上一答中的**具体词句**，证明在听。
3. 出现以下信号时，**不往下潜，就地深挖**：
   - 只有形容词没有动作（「我负责统筹」）
   - 只有团队没有个人（「我们完成了」）
   - 只有结果没有过程（「最后效果很好」）
4. 连续两轮在同一层打转，说明储备不足 → 停止追问，给出示范答法，再重问一次。
5. 单场十轮不重复；每题可追溯至某个事实编号。

### 5.3 三场景差异

| 场景 | 出题依据 | 追问重点 | 层数上限 | 对数字的态度 |
|---|---|---|---|---|
| 综合面 | 简历经历 + 求职动机 | 归因、反思、稳定性 | 3 | 温和确认 |
| 专业面 | JD 硬性要求 + 项目细节 | 方法、边界、取舍 | 3 | 追问依据与来源 |
| 压力面 | 清单里最虚的条目 | 反复追问同一缺口 | 4+ | 直接质疑「这算你的功劳吗」 |

⚠️ **三种场景若只在题库上不同，等于一张皮。** 必须在「层数上限 / 是否质疑 / 复盘权重」三处同时体现差异，否则录屏里看起来完全一样。

### 5.4 复盘报告与两套五维

报告结构见 [`01-需求分析.md`](01-需求分析.md) 附录 A.1，核心字段：

```
report_id / resume_version / target_role / scene / rounds
scores（五键） / total / match_level
per_question[]（qid, fact_id, question, intent, expect, actual, gap, star）
gaps[]（id, desc, fact_id, source, suggestion, status）
resume_advice
```

`intent` 是出题意图（这道题想验证什么），`expect` 是学生想表达什么，`actual` 是实际答成什么，`gap` 是差在哪——合起来对应 2.6 的「问了什么 / 你想表达什么 / 实际答成什么 / 差在哪」四栏，缺一栏即不合格。

**面试能力五维**（与 3.2 的职业能力五维是两套，不合并、不互相换算）：

| 键名 | 维度 | 权重 |
|---|---|---|
| `tech_depth` | 技术深度 | 30% |
| `project` | 项目经验 | 25% |
| `logic` | 表达逻辑 | 20% |
| `behavior` | 行为素质 | 15% |
| `fit` | 岗位匹配度 | 10% |

```
总分 = Σ(各维分数 × 权重) × 10，四舍五入取整
```

例：`7×0.30 + 8×0.25 + 6×0.20 + 5×0.15 + 7×0.10 = 6.75` → **68 分**

| 总分 | 结论 |
|---|---|
| ≥ 85 | 强烈推荐 |
| 70–84 | 推荐 |
| 50–69 | 有潜力 |
| < 50 | 建议调整目标 |

**点评禁止**：「你很棒」「表达流畅」这类无信息量评语。每条评价必须引用学生原话，并跟一个可执行动作（「下次这样说：……」）。卡点须对应回事实清单中结果为【待核实】或证据强度为虚的条目。

## 六、边界与拒答

### 6.1 三类必须拒绝的请求

| 请求 | 判定 | 应对话术方向 |
|---|---|---|
| 「帮我编一段实习经历」 | 事实虚构 | 说明风险：背调与追问都会露；转为「把你真实做过的事写到最好」 |
| 「把这个项目写成我主导的」 | 归因夸大 | 区分「参与」与「主导」的证据差异；建议如实标注贡献边界 |
| 「面试时问到不会的怎么撒谎」 | 诚信风险 | 给真实可行的应对框架：承认边界 + 迁移能力 + 学习计划 |

**这三条不是技术限制，是产品底线。** 它也是答辩加分项——证明团队想过「这东西被用坏了会怎样」。

### 6.2 能力边界（做不到就直说）

- 无法核实简历真实性（无数据源）
- 无法解析扫描件与图片简历（明确提示改用粘贴）
- 无法替代真实 HR 的岗位判断（只能做通用匹配）
- 无法保证面试通过（只提升表达与结构）

### 6.3 数据治理

- 学生可一键清除本人会话、清单与报告，清除后任一字段检索不到
- 手机号、身份证号、邮箱须被识别并提示，可指令替换为脱敏文本
- 不采集院校信息，不建账号体系

## 七、提示词分层

| 层 | 位置 | 内容 | 谁维护 |
|---|---|---|---|
| 系统层 | `server/prompts/diagnosis.md` / `interview.md` / `review.md` | 单模块的角色、流程、禁令 | 各模块负责人 |
| 资产层 | `references/*.md` | 量规、题库、句式库、模板 | 按资料专人负责 |
| 状态层 | 服务端 session | 版本号、锁定岗位、事实清单、轮次与层级 | 后端组 |
| 任务层 | 学生当次输入 | 简历、JD、回答 | 学生 |

**分层纪律：** 不在指令里重复写人设，也不把量规正文塞进指令（量规走资产层，按需挂载）。混层会让提示词越改越乱，且无法定位问题出在哪一层。

## 八、失败模式与兜底

| 失败模式 | 表现 | 兜底策略 |
|---|---|---|
| 输出泛化 | 全是「建议突出亮点」这类空话 | 强制输出模板：每条必须带原文片段与修改方向 |
| 编造数字 | 改写中出现原文没有的量化结果 | 改写前后做实体比对，数字只减不增 |
| 分数漂移 | 同一简历两次诊断差 20 分 | 固定权重 + 低温度 + 量规分档，波动超 5 分即重跑 |
| 追问退化 | 连着几轮问同一层 | 计数：同层两轮即切换策略 |
| 一题多问 | 一轮输出两个问号 | 正则拦截，回退重生成 |
| 上下文丢失 | 长对话后忘了岗位 | 每轮开头从 session 复述岗位与锚定事实编号 |
| 解析失败 | 扫描件读不出内容 | 显式报错 + 引导粘贴，不得静默降级 |
| 材料不全 | 没 JD / 没简历 | 降级模式：通用诊断 + 明确告知局限 |
| 报告不一致 | 页面与导出 HTML 内容不同 | 同一份 JSON 渲染两处，不生成第二份真相 |
