# 01 · 需求分析

> 本文回答四个问题：给谁做、解决什么、为什么现有方案不够、做到什么程度算成功。

---

## 一、问题定义（一句话）

毕业生不是不会写简历，而是**不知道自己写的东西在 HR 眼里值多少分**；不是不敢面试，而是**没有一个人愿意陪他连问四十个问题再告诉他哪里崩了**。

---

## 二、现状与背景

### 2.1 供需失衡的结构性事实

- 一名高校就业指导老师通常对口数百名毕业生，能提供的只有群体讲座、模板发放、少量一对一预约。
- 一对一简历精修的市场价从数百到上千元不等，对多数学生是奢侈品。
- 秋招与春招的窗口期集中在 2—3 个月内，学生的修改迭代次数被时间硬性压缩。

### 2.2 学生端的三类典型失败

| 失败类型 | 表面症状 | 真实成因 |
|---|---|---|
| **空话型** | 满篇「沟通能力强」「学习能力突出」 | 不了解简历的评价单位是**证据**而非形容词 |
| **错位型** | 把同一份简历投所有岗位 | 不知道要按 JD 关键词重排经历顺序 |
| **裸奔型** | 面试时背稿，被追问第二层就崩 | 从未经历过多轮追问，缺乏临场组织语言的肌肉记忆 |

---

## 三、用户画像

### P0 · 应届毕业生（核心用户）

- 本科 / 硕士，毕业前 3—9 个月
- 手上有一份或几份简历，但不确定好坏
- 目标：拿到面试机会，并在面试中不崩
- 使用时机：投递前夜、面试前一天、被拒之后

### P1 · 就业指导老师 / 辅导员（次要用户）

- 需要批量为学生做初筛反馈
- 目标：把有限的面对面时间留给最需要的人
- 对我们意味着：输出必须**可批量复用**、结论要能直接转给学生

### P2 · 转行 / 实习申请者（延展用户）

- 有工作经历但与目标岗位不对口
- 目标：把已有经历「翻译」成目标岗位听得懂的语言

---

## 四、痛点拆解

### 4.1 简历侧

1. **缺评价标准**——学生不知道「好」长什么样，只能凭感觉。
2. **缺证据意识**——不知道「做了什么」要落到「量化结果」。
3. **缺岗位视角**——不知道 HR 是拿 JD 关键词做匹配的。
4. **缺迭代反馈**——改完没人告诉他有没有变好。

### 4.2 面试侧

1. **缺练习对象**——同学互练容易互相客气，问不到第二层。
2. **缺追问压力**——真实面试的杀伤力来自追问，模拟时没人追问。
3. **缺结构化复盘**——面完只知道「感觉不好」，说不出哪里不好。
4. **缺岗位针对性**——通用题库和真实岗位问题差距大。

> 四类痛点里有三类的共同内核是**缺一个不知疲倦、不留情面、还能说清理由的对手**。这正是智能体相对人工服务的结构性优势，也是本项目存在的理由。

---

## 五、现有方案与不足

| 方案 | 优势 | 不足 |
|---|---|---|
| 模板网站 / 简历生成器 | 免费、上手快 | 只解决排版，不解决内容质量 |
| 学长学姐帮忙看 | 有经验、可信 | 供给不稳定，标准因人而异，不好意思麻烦多次 |
| 付费简历精修 | 专业 | 贵、周期长、一次性 |
| 通用大模型直接问 | 便宜、随时可用 | 一次问全导致输出泛化；不追问、不给分数、不留档，无法迭代 |

**我们的位置**：在「通用大模型」和「付费一对一」之间，用**流程化 + 知识库 + 多轮追问**补上通用模型缺的那部分严谨性。

---

## 六、需求清单与优先级

采用 MoSCoW 分级。**Must 项构成 MVP，是分享链接上线前必须全部跑通的范围。**

### Must（必须有）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| M1 | 简历解析：接受粘贴文本或文档，结构化出教育、经历、项目、技能四块 | 三类样本各测一份，字段抽取完整 |
| M2 | 简历诊断：按「量化证据 / 岗位匹配 / 结构清晰 / 表达冗余」四个维度打分并给理由 | 每条扣分都能定位到原文片段 |
| M3 | 定向改写：基于目标 JD 重写指定条目，只改表达不改事实 | 改写前后事实实体一致，无新增虚构 |
| M4 | 模拟面试：按岗位生成问题，支持至少 3 层追问 | 追问能基于上一轮回答的缺口，而非固定题库 |
| M5 | 面试复盘：输出结构化报告（表达 / 结构 / 证据强度 / 改进动作） | 报告含可执行动作，非泛泛评价 |

### Should（应该有）

| 编号 | 需求 | 说明 |
|---|---|---|
| S1 | 岗位 JD 解析：提取硬性要求与关键词 | 作为 M3 的输入前置 |
| S2 | 分数可视化：诊断出总分与分项分 | 便于演示前后对比 |
| S3 | 训练留档：同一用户多次训练可对比 | 体现「越练越好」的价值 |
| S4 | 拒答与劝导：拒绝代写虚构经历 | 见 `03-逻辑梳理.md` 第五节 |

### Could（可以有）

- 多行业题库切换（互联网 / 制造 / 金融 / 教育）
- 英文简历与英文面试模式
- 面试录音转写后复盘

### Won't（明确不做）

- 不做简历模板排版与导出（排版是模板网站的地盘，不抢）
- 不做岗位投递与内推对接（涉及外部系统授权与合规，超出范围）
- 不做简历真实性核验（没有数据源，无法做，硬做就是幻觉）

## 七、非功能需求

| 维度 | 要求 | 原因 |
|---|---|---|
| **隐私** | 不长期存储用户简历原文；演示与截图一律脱敏 | 简历是高频个人信息载体，一旦泄露后果严重 |
| **诚实** | 所有扣分必须能指向原文，禁止无依据评价 | 不可解释的建议对学生无价值，且会误导 |
| **边界** | 明确拒绝代写与虚构 | 涉及求职诚信，是产品底线而非技术限制 |
| **响应** | 单轮诊断类输出控制在一次交互内完成 | 多轮往返会打断学生思路 |
| **可控** | 关键结论用固定结构输出，便于比对 | 支持前后对比与批量使用 |

---

## 八、成功指标

### 8.1 效果指标（作品价值证明）

| 指标 | 定义 | 目标 |
|---|---|---|
| 诊断定位率 | 扣分项能定位到原文具体片段的比例 | ≥ 90% |
| 改写事实保持率 | 改写后未引入原文不存在的事实 | 100% |
| 追问有效率 | 追问基于上一轮回答缺口而非通用题库的比例 | ≥ 70% |
| 建议可执行率 | 复盘报告中含明确动作（改哪句、怎么改）的比例 | ≥ 80% |

### 8.2 演示指标（决赛对比用）

- 同一份简历诊断前后的分项分变化
- 同一岗位模拟面试，第 1 轮与第 3 轮的回答结构化程度对比
- 人工一对一辅导所需时间 vs 智能体完成同等反馈所需时间

---

## 九、假设与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 用户简历为图片 / 扫描件 | 无法解析，主流程断裂 | MVP 明确要求文本或可复制文档；图片走提示用户转文本 |
| 用户不提供目标岗位 | 无法做定向改写，只能做通用诊断 | 降级为「通用诊断模式」，并引导补充岗位 |
| 模型倾向过度美化用词 | 改写变成堆形容词，反而更空 | 提示词强约束「只允许替换为可验证表达」 |
| 演示样本含真实个人信息 | 违反匿名要求 | 全部使用自造样本，见 `assets/screenshots` 约定 |
