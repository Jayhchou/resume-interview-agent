## 一、赛题与范围

本项目是面向在校生的就业能力训练系统。流程分六步：简历接入与在线编辑、五维诊断、定向改写、事实清单、模拟面试、结构化复盘，最后接一轮二次训练，同一份简历可以反复练。与常见的 AI 改简历工具相比，有两条硬约束：改写不新增原文没有的事实，面试只问简历里真实存在的经历。

整条链路首尾相接：简历原文或空白模板 → 结构化稿件 → 五维诊断 → 事实清单 → 面试会话 → 复盘报告 → 下一版简历回到修改环节。事实清单全流程共用一份，由简历侧产出，也是面试侧唯一的输入。

> **形态说明**　本系统以自建 Web 应用形式交付：前端是浏览器打开的独立页面，后端服务承接文件解析、模型调用与会话状态。访问不设门槛，学生打开链接即可使用，无需注册，无需安装。页面分三块——简历工作区（上传、从零录入、按条修改）、对话区（诊断、改写、面谈）、报告区（五维雷达图、分数条、成长曲线与可下载的 HTML 报告），三块同页联动，不来回跳转。专业逻辑放在后端：三段系统指令分别对应诊断、面谈、复盘，评分量规、题库与句式库以文件形式随代码交付，提示词独立成篇、可版本替换，不写死在代码里。模型调用统一走服务端网关，密钥只存在于服务端环境变量，前端不接触。

本文范围　只回答两个问题：系统要满足哪些业务场景，技术上必须做到什么。开发排期、接口文档、数据表设计、演示脚本与答辩话术不在本文范畴，属开发计划与详细设计，另立文档。

| 维度 | 要求 |
|---|---|
| 开发底座 | 自建 Web 应用：前端页面 + 后端服务，全程在 WorkBuddy 平台内开发与发布 |
| 模型接入 | 后端统一网关调用大模型，密钥置于服务端环境变量；前端不直连模型、不持有密钥 |
| 访问方式 | 发布后获得公网链接，浏览器打开即用，无需注册与安装；窄屏可正常使用 |
| 测试数据 | 虚构简历 ≥ 6 份（覆盖单页、双页、扫描件）、目标岗位 ≥ 5 个、事实清单 ≥ 30 条、空白模板 3 套（单页 / 双页 / 项目型） |
| 交付物 | 可访问的 Web 应用链接、需求分析与系统设计文档、演示视频、答辩 PPT |

## 二、业务场景需求

系统只解决一件事：让学生在真实投递之前，把简历里的经历练到经得起追问。七个场景按链路顺序排列，前一环的输出就是后一环的输入。

### 2.1 简历接入与在线编辑

谁用：学生

做什么：两条入口——上传已有简历（PDF、DOCX 或粘贴文本）由系统解析为结构化稿件，或从空白模板从零录入；两种来源进入同一套修改流程，按「基本信息 / 教育 / 经历 / 项目 / 技能」五块逐块核对。修改以指令完成：说「第二条经历补上并发优化的结果」即改写该条，说「把项目移到教育前面」即调整顺序，增删同理；每次改完回显当前完整稿件，确认后升版本，可导出 DOCX

验收要点：解析结果须落到五类字段，只存原文不算完成；上传稿与新建稿的字段结构一致，同一套指令都适用；每次修改后须回显完整稿件，学生确认过的稿件与实际导出的 DOCX 一致，条目顺序与时间格式不得错位；五类字段全空时不得进入诊断

### 2.2 五维诊断

谁用：学生

做什么：选目标岗位 → 按固定权重输出职业能力五维分数与加权总分 → 每维给出不超过三条问题，附原文引用

| 维度 | 权重 | 评估依据（取自简历原文） |
|---|---|---|
| 专业基础 | 20% | 课程、证书、技能栈与目标岗位要求的重合度 |
| 实践经历 | 30% | 实习、项目、竞赛的时长、真实性与覆盖面 |
| 成果产出 | 20% | 结果是否有数字或可验证物，与角色是否匹配 |
| 沟通表达 | 15% | 句子是否讲清动作与对象，条目能否快速扫读 |
| 协作推进 | 15% | 事实清单中的角色（主导 / 参与 / 协助）与协作规模 |

验收要点：分数须能拆到维度并给出依据，只给总分视为不可解释；同一稿件连跑两次，各维波动不超过五分；岗位匹配度以会话内锁定的 JD 技能要求计重合率，可人工复算，不随检索结果变化

### 2.3 定向改写

谁用：学生

做什么：指定任一低分句（引原句或说第几条）→ 得到「原句 / 问题诊断 / 改写示例 / 需你补充的信息」四联对照 → 按提示补齐信息后可二次改写

验收要点：任取十条改写比对原文，事实增量为零，不得出现原文没有的数字、公司、时间；无法改写时须输出「需补充信息」而非硬编；每条须说明改动理由，只给结果不达标

### 2.4 事实清单生成

谁用：学生（产出），面试模块（消费）

做什么：诊断完成后自动抽取为六字段事实清单 → 学生就地编辑「角色」与「结果」→ 缺失项标【待核实】→ 修改即升版本号

验收要点：字段顺序固定，任一字段缺失即视为结构错误；结果缺失一律留【待核实】，出现推测数字即为红线违规；事实句中不得出现形容词，可正则抽检

| 字段 | 含义 | 约束 |
|---|---|---|
| id | 事实编号 E1 、 E2…… | 全生命周期不变 |
| 事实句 | 在哪、做了什么、用什么方法 | 不含形容词，只陈述动作与对象 |
| 结果 | 带数字或可验证的事实 | 缺失写【待核实】，禁止推测补全 |
| 角色 | 主导 / 参与 / 协助 / 独立 | 四选一，由学生本人确认 |
| 证据强度 | 强 / 中 / 虚 | 由「结果是否有数字」与「角色是否明确」判定 |
| 追问链 | 预设两到三层下潜问法 | 供面试模块直接取用 |

### 2.5 模拟面试

谁用：学生

做什么：选场景（综合面 / 专业面 / 压力面）与轮次 → 完成开场三确认 → 系统逐题单问、逐层追问 → 五至十轮后结束

验收要点：题目须跟着事实清单走，全员同一套开场题不达标；一轮只能提一个问题；回答出现「只有形容词没动作」「只有团队没个人」「只有结果没过程」时须就地深挖而非换题

### 2.6 结构化复盘

谁用：学生

做什么：输出总分与技术深度、表达逻辑、项目经验、行为素质、岗位匹配度五维分数 → 逐题点评（问了什么 / 你想表达什么 / 实际答成什么 / 差在哪）→ 卡点清单 → 针对卡点的简历补充建议 → 生成可下载的 HTML 报告，含五维雷达图与分数条

验收要点：点评须引用学生原话，禁止「你很棒」类无信息量评语；评分取面试能力五维，与 2.2 的职业能力五维分开统计，不得混用；每个卡点须对应回事实清单中结果为【待核实】或证据强度为虚的条目

### 2.7 二次训练与成长曲线

谁用：学生

做什么：按复盘建议通过对话补齐经历 → 重跑五维诊断 → 查看同一份简历的分数变化 → 再练一轮面试，观察同一批卡点是否收敛

验收要点：改后重测须出现两个及以上数据点；已补齐的卡点标记为「已解决」，而非重复列出

二次训练决定这套系统是不是一次性的。跳过它，前面六步做完就结束，只留下几段文案；加上它，同一份简历才有两次以上的分数可对比，教学效果也才有数据可讲。

### 2.8 数据边界与匿名机制

系统不建立自己的账号体系，学生用访问链接直接进入，不填手机号与院校信息。边界不清会让演示数据与真实数据混在一起，下表作为数据治理与测试用例的依据。

| 数据 | 学生 | 演示者 | 服务端 |
|---|---|---|---|
| 简历原文 | 上传、编辑、导出、删除 | 仅虚构样本，可走一遍编辑与导出 | 不留存明文；样本全程虚构 |
| 诊断与改写 | 本人可见 | 只读 | 不留存明文 |
| 事实清单 | 增改查 | 只读 | 不留存明文 |
| 面试会话 | 本人可见 | 只读 | 不留存明文 |
| 成长曲线 | 仅本人 | 全部 | 脱敏统计 |

## 三、功能需求清单

二十五个功能点按链路编号 FR-模块.条目，每条附验收标准，作为开发完成与演示对答的依据。

| 编号 | 模块 | 需求 | 验收标准 |
|---|---|---|---|
| FR-1.1 | 简历接入与编辑 | 支持 PDF 、 DOCX 上传与纯文本粘贴 | 三类样本均能解析；扫描件明确提示改用粘贴，不得静默失败 |
| FR-1.2 | 简历接入与编辑 | 解析结果落到五类字段 | 五类字段可分别查看与编辑，只存原文不算完成 |
| FR-1.3 | 简历接入与编辑 | 上传稿与空白新建走同一套修改流程 | 两种来源下五类字段结构与可用指令完全一致，缺一视为未完成 |
| FR-1.4 | 简历接入与编辑 | 以指令完成条目增删、顺序调整、逐句改写 | 任一指令执行后回显完整稿件；改错可指令回退 |
| FR-1.5 | 简历接入与编辑 | 导出 DOCX 成稿 | 导出文件条目顺序与时间格式同确认稿一致 |
| FR-1.6 | 简历接入与编辑 | 确认即升版本，可对比差异 | 版本号递增可回溯；可列出任意两版的差异条目 |
| FR-2.1 | 五维诊断 | 按固定权重输出五维分数与加权总分 | 权重不可配置；总分等于五维加权，可手工复算 |
| FR-2.2 | 五维诊断 | 每维给出不超过三条问题，附原文引用 | 抽检任一问题，能在原文定位到对应句子 |
| FR-2.3 | 五维诊断 | 分数稳定性约束 | 同一简历连跑两次，各维波动不超过五分 |
| FR-3.1 | 定向改写 | 四联对照展示 | 原句、问题、示例、需补充四栏齐全，缺一视为未完成 |
| FR-3.2 | 定向改写 | 改写不得新增事实 | 任取十条比对原文，事实增量为零 |
| FR-3.3 | 定向改写 | 说明改动理由 | 每条附一句为何这样改，只给结果不达标 |
| FR-4.1 | 事实清单 | 生成六字段结构化清单 | 字段顺序固定，缺失项写【待核实】 |
| FR-4.2 | 事实清单 | 就地编辑角色与结果并升版本 | 改动后版本号递增，历史版本可回溯 |
| FR-4.3 | 事实清单 | 事实句禁止形容词 | 正则抽检「优秀、丰富、良好、突出」，命中即不合格 |
| FR-5.1 | 模拟面试 | 开场三确认后方可提问 | 场景、岗位、轮次缺一，不得进入答题 |
| FR-5.2 | 模拟面试 | 单轮仅提一个问题 | 输出含两个及以上问号即判不合格，须回退重生成 |
| FR-5.3 | 模拟面试 | 沿五层模型追问，达上限换题 | 单场十轮不重复；每题可追溯至某个事实编号 |
| FR-5.4 | 模拟面试 | 三场景参数差异生效 | 同一简历在三场景下，追问深度与质疑强度可观测不同 |
| FR-6.1 | 结构化复盘 | 输出五维分数、逐题点评与卡点清单 | 点评引用学生原话；卡点对应清单薄弱项，交叉一致率不低于八成 |
| FR-6.2 | 结构化复盘 | 报告可导出为文本与 HTML | Markdown 与 HTML 双形态，HTML 含五维雷达图与分数条，内容与复盘中已确认的结论一致 |
| FR-7.1 | 成长档案 | 展示同一简历的五维分数变化 | 改后重测出现两个数据点，差值合理 |
| FR-7.2 | 成长档案 | 卡点收敛追踪 | 已补齐的卡点标记为已解决，不重复列出 |
| FR-8.1 | 数据治理 | 清除本人会话与记录 | 清除后会话、清单、报告中检索不到任一字段 |
| FR-8.2 | 数据治理 | 敏感信息识别与脱敏 | 手机号、身份证号、邮箱须被识别并提示，可指令替换为脱敏文本 |

## 四、技术需求

技术需求分三部分：系统架构与能力落地、AI 能力要求、数据准备。评审主要看两件事：流程是不是真的由大模型驱动，工程实现是不是站得住。

### 4.1 系统架构与能力落地

下列六项必须有明确落点。常见失分是页面做得漂亮、后端只有一段长提示词：解析没做、状态不存、换个问法就答不下去。

| 能力 | 本系统的落点 | 落地要求 |
|---|---|---|
| 前端交互 | 简历工作区、对话区、报告区三块同页 | 上传、编辑、对话、看报告不跳页；窄屏纵向堆叠，功能不裁 |
| 后端服务 | 路由、文件解析、会话状态、模型调用 | 模型密钥只在服务端；解析失败须显式报错，不得静默降级 |
| 智能体逻辑 | 三段角色指令，对应诊断、面谈、复盘三个模块 | 按「角色 / 流程 / 禁令」三层写，禁令单列，不与流程混写 |
| 知识资产 | references 下的量规、题库、句式库、报告模板 | 以文件形式随代码交付，改内容不动代码；每份标注版本 |
| 会话状态 | 轮次、层级、锚定事实编号、当前模块 | 服务端持有 session，刷新不丢；不同访客不串数据 |
| 匿名访问 | 链接即入口，不建账号体系 | 会话隔离；不采集手机号与院校信息 |

模块拆分　三个模块各带自己的参考资料：简历诊断带评分量规、五类字段定义与句式库，同时承载定向改写；模拟面试带题库与 STAR 标准；复盘带报告模板与卡点判定规则。改一份资料不影响其他模块，也不必动页面与路由。

### 4.2 AI 能力技术要求

| AI 功能 | 稳妥做法 | 判定点 |
|---|---|---|
| 五维诊断 | 先抽取字段与证据，再按量规逐维给分，模型只写问题描述 | 同一简历两次诊断波动不超过五分 |
| 定向改写 | 从挂载的句式库取模板，模型只做填空与重组 | 事实增量为零，无新增数字与公司 |
| 事实清单 | 按固定字段模板抽取，模型只做归并与去重，结果字段留空待填 | 缺失一律【待核实】，不出现推测数字 |
| 面试追问 | 轮次规则写进指令，模型在给定事实编号与层级内出题 | 单轮仅一个问号；每题可追溯来源 |
| 复盘评分 | 固定 rubric 、分维度打分、低温度参数 | 同一段回答重复评，分数不漂移 |

原则　能算的不要让模型猜，让它做「解释」而不是做「判断」。另有两件事要提前办：确认模型 API 额度足够跑完一整条链路；提示词、温度参数、评分量规写进系统设计说明书的对应章节，评审会翻这些地方。

### 4.3 数据准备要求

构造数据有两点要求：一是简历要覆盖不同质量层次，至少留出两份明显薄弱的样本，否则诊断与追问看不出差别；二是岗位要有梯度，技术、运营、设计各留一个，避免所有简历都匹配到同一个岗位。

| 数据类别 | 数量下限 | 关键字段 |
|---|---|---|
| 虚构简历 | ≥ 6 份 | 单页 PDF 、双页 DOCX 、扫描件各两份；覆盖技术、运营、设计三个方向 |
| 目标岗位 | ≥ 5 个 | 岗位名称、企业类型、技能要求、经验要求、学历要求 |
| 事实清单样本 | ≥ 30 条 | 六字段齐全，其中不少于八条结果为【待核实】 |
| 面试脚本 | 3 套 | 对应综合面、专业面、压力面，各含十轮参考问答 |
| 空白模板 | 3 套 | 单页、双页、项目型各一套，字段与五类分区对应 |

### 4.4 数据来源与知识库构成

数据的来源与去向分三类：评分量规、题库、岗位基线库属自建资产，随项目仓库一同交付，改内容不动代码；学生上传的 JD 与临时检索到的岗位要求属运行时数据，只在当次会话使用，不写入文件；简历样本全部虚构，只用于演示。

| 数据类别 | 获取方式 | 承载位置 | 落地要求 |
|---|---|---|---|
| 评分量规 | 自建，按行为锚定写法分档 | 后端 references/ | 每维四档各补 2 至 3 条可判定行为特征；只改档位描述，不动流程 |
| 面试题库 | 自建，按岗位与考察点整理 | 后端 references/ | 每题标岗位、难度、考察点；题干可复用，具体问法须结合事实编号重写 |
| 岗位基线库 | 自建，8 至 12 个常见校招岗位 | 后端 references/ | 每岗五字段齐全：名称、企业类型、技能要求、经验要求、学历要求；作为默认参照 |
| 学生自带 JD | 学生粘贴 | 服务端会话内，不落文件 | 优先于基线库；抽成五字段后锁存，当次会话不再变更 |
| 岗位实时要求 | 联网检索，学生显式触发 | 服务端会话内，不落文件 | 结果当场转成五字段并注明来源与日期；检索失败回落基线库，不得中断 |
| 简历样本 | 全部虚构 | 演示数据 | 不使用任何真实简历；至少两份明显薄弱，否则诊断与追问看不出差别 |

知识库的边界　平台知识库（资料库、ima 等）的授权绑定在创建者账号上，调用凭据不能随作品分发，网页访客也进不了该知识库的空间。因此知识库只作素材来源，不作运行时依赖：凡需要学生用到的资料，开发阶段一次性采集，落成项目内 references 下带版本号的 Markdown 文件，随代码一同发布；更新时重新采集并提升版本号，不在运行时实时检索。同一道理，真实学生简历、招聘平台抓取的页面、培训机构付费资料这三类材料不进入项目，简历样本全部虚构。

岗位匹配度的算法　这一维不交给模型判断「像不像」。取会话内已锁定的 JD 技能要求，与简历技能栈做词集合匹配，以重合项数除以要求项数得分，再按权重计入总分，可人工复算。基准在诊断开始时确定，诊断、出题、复盘全程共用同一份，不因二次检索而改变，2.2 那条波动要求由此可兑现。

项目结构　前端、后端、知识资产、系统指令分开放：改一份参考资料不影响代码，换一版提示词也不必重打包页面。建议结构如下。

## 附录 数据结构与接口约定

本附录是开发对接用的约定，不属于业务场景描述。四部分内容：复盘报告的字段结构、面试能力五维的权重与总分算法、三个模块的输入输出、会话状态存放。字段名与取值范围一旦定下，后端生成与前端渲染都以此为准，双方不得各自扩展。

### A.1 复盘报告字段结构

报告统一以 JSON 输出。顶层字段见下表，per_question 与 gaps 是数组，子字段另表列出。

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| report_id | 字符串 | R-年月日-序号 | 每次复盘唯一 |
| resume_version | 字符串 | V1、V2… | 对应简历版本号 |
| target_role | 字符串 | 岗位名称 | 与诊断时的目标岗位一致 |
| scene | 字符串 | 综合面 / 专业面 / 压力面 | 三选一 |
| rounds | 整数 | 5 至 10 | 实际提问轮数 |
| scores | 对象 | 五键，各 1 至 10 | 键名见 A.2 |
| total | 整数 | 0 至 100 | 由 A.2 公式算出 |
| match_level | 字符串 | 四级 | 由 total 映射，见 A.2 |
| per_question | 数组 | 见下表 | 逐题点评 |
| gaps | 数组 | 见下表 | 卡点清单 |
| resume_advice | 字符串 | 不限 | 针对卡点的简历补充建议 |

per_question 子字段

| 字段 | 类型 | 说明 |
|---|---|---|
| qid | 字符串 | 题号 Q1、Q2… |
| fact_id | 字符串 | 锚定的事实编号 E1、E2…，不得为空 |
| question | 字符串 | 实际提出的问题 |
| intent | 字符串 | 这道题想验证什么 |
| actual | 字符串 | 学生的实际应答，须引用原话 |
| gap | 字符串 | 差在哪 |
| star | 对象 | S、T、A、R 四个布尔值，缺失为 false |

gaps 子字段

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 字符串 | G1、G2… |
| desc | 字符串 | 卡点描述 |
| fact_id | 字符串 | 对应事实编号，须能在清单中定位 |
| source | 字符串 | 结果待核实 / 证据强度虚 |
| suggestion | 字符串 | 补齐建议 |
| status | 字符串 | open 或 solved，二次训练后回写 |

一份完整报告的最小示例

```json
{
  "report_id": "R-20261102-001",
  "resume_version": "V1",
  "target_role": "后端开发",
  "scene": "专业面",
```

### A.2 面试能力五维权重与总分

五维取后端配置的维度，各维 1 至 10 分。权重如下，与 2.2 的职业能力五维是两套，不合并、不互相换算。

| 键名 | 维度 | 权重 |
|---|---|---|
| tech_depth | 技术深度 | 30% |
| project | 项目经验 | 25% |
| logic | 表达逻辑 | 20% |
| behavior | 行为素质 | 15% |
| fit | 岗位匹配度 | 10% |

总分 ＝（各维分数 × 权重）之和 × 10，四舍五入取整。以上例：7×0.30 ＋ 8×0.25 ＋ 6×0.20 ＋ 5×0.15 ＋ 7×0.10 ＝ 6.75，总分 68。

| 总分 | 结论 |
|---|---|
| ≥ 85 | 强烈推荐 |
| 70 至 84 | 推荐 |
| 50 至 69 | 有潜力 |
| < 50 | 建议调整目标 |

### A.3 三个模块的输入输出

模块之间不传参，下游从会话状态读取上游结果。上游缺失时按「缺失时行为」处理，不得自行推测补全。

| 模块 | 输入 | 输出 | 缺失时行为 |
|---|---|---|---|
| 简历诊断 | 五类字段的结构化简历、目标岗位、评分量规 | 职业能力五维分数与加权总分；每维不超过三条问题，附原文引用。定向改写同属本模块，输出四联对照 | 五类字段有空项时列出缺项，暂不出分 |
| 模拟面试 | 六字段事实清单、场景、轮次 | 逐题问答记录，每题标注锚定的事实编号 | 事实清单为空时先索要，不直接出题 |
| 复盘出报告 | 问答记录、事实清单、评分量规、报告模板 | A.1 定义的 JSON 与 HTML 报告 | 有效轮次不足五轮时出简版报告并标注 |

### A.4 会话状态存放

成长曲线需要两次以上数据点，状态须跨访问留存。存放有三种可选，按下表取舍。

| 方案 | 做法 | 取舍 |
|---|---|---|
| 浏览器本地存储 | 报告与简历版本存 localStorage，下次打开按同一浏览器续接 | 零后端成本，演示够用；清缓存即丢，换设备不迁移 |
| 服务端会话库 | 服务端按匿名标识存报告，访问时读取 | 体验最好，需持久化存储；标识仅用于续接，不等于账号 |
| 导出再导入 | 报告导出为 JSON，下次上传恢复 | 兜底方案，任何时候都能跑完整条链路 |

演示阶段建议第二种起步，保证两轮跑得通；正式版沿用第二种并加持久化；第三种作为兜底，任何时候都能跑完一整条链路。
