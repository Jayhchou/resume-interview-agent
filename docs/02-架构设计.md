# 02 · 架构设计

> 本文回答：系统由哪几块组成、每块的边界在哪、为什么这样切。
> 与 [`01-需求分析.md`](01-需求分析.md) 的口径严格对齐；两者冲突时以 01 为准。

---

## 一、总体架构

采用「**四区分离**」结构：页面只管表现，服务只管调度，逻辑写进三段指令，知识与素材以文件形式随代码交付。

```
┌──────────────────────────────────────────────────────────┐
│  表现层   web/                                            │
│  简历工作区 · 对话区 · 报告区（三块同页，不跳转）           │  ← 浏览器
├──────────────────────────────────────────────────────────┤
│  服务层   server/                                         │
│  路由 · 文件解析 · 会话状态 · 模型网关 · 报告渲染          │  ← 服务端
├──────────────────────────────────────────────────────────┤
│  逻辑层   server/prompts/                                 │
│  诊断（含定向改写） · 模拟面试 · 复盘出报告                │  ← 三段系统指令
├──────────────────────────────────────────────────────────┤
│  资产层   server/kb/                                      │
│  量规 · 题库 · 句式库 · 岗位基线 · 模板                    │  ← 随代码交付
└──────────────────────────────────────────────────────────┘
        数据层   data/samples/   虚构简历与空白模板
```

### 1.1 为什么不是「漂亮页面 + 一段长提示词」

赛事评审最常看到的失分形态：前端做得很好看，后端只有一段万能提示词。表现是——换个问法就崩、刷新页面就失忆、追问两轮就忘了岗位。

| 能力 | 一段长提示词的结局 | 本系统的落点 |
|---|---|---|
| 文件解析 | 让模型「读懂」PDF，扫描件直接瞎编 | 服务端解析成五类字段，失败显式报错 |
| 会话状态 | 靠对话历史硬撑，几轮后漂移 | 服务端 session 持有轮次、层级、锚定事实编号 |
| 可复现 | 同一份简历两次打分差 20 分 | 量规固定权重、低温度、可人工复算 |
| 可维护 | 改一句话要重跑整条链路 | 改 `server/kb/` 的 JSON 不动代码，换提示词不重打包页面 |

**核心判断：能算的不要让模型猜，让它做「解释」而不是「判断」。**

### 1.2 与上一版「专家包」形态的取舍

本项目早期按平台专家形态设计（一个专家 + 两个技能 + 分享链接）。转向自建 Web 后，原有的分层并未浪费，而是换了承载体：

| 原形态 | 现在 | 是否保留 |
|---|---|---|
| 专家人设与总提示词 | 三块页面的固定引导语 + `prompts/` 三段指令的开头 | 改造保留 |
| 技能（`SKILL.md`） | `server/prompts/` 下的三段系统指令 | 保留，换了载体 |
| 资料库（平台知识库） | `server/kb/` 下的 JSON（源头整理稿在 `references/`） | 保留，改为随代码交付 |
| 共享链接（绑定账号） | 公网 URL，匿名访问 | 替换 |
| 连接器（读 PDF/JD） | 服务端本地解析 + 会话内 JD 粘贴 | 替换为自建 |

退役原因见 [`01-需求分析.md`](01-需求分析.md) 一、赛题与范围：平台知识库的授权绑定在创建者账号上，调用凭据无法随作品分发，网页访客也进不了该知识库空间——因此知识库只能作素材来源，不能作运行时依赖。

## 二、表现层：三块同页

### 2.1 三个区域

| 区域 | 职责 | 关键交互 | 不能做 |
|---|---|---|---|
| **简历工作区** | 上传 / 从零录入 / 按条修改 / 版本对比 / 导出 DOCX | 以指令改稿（「第二条补上并发优化的结果」） | 不做诊断给分 |
| **对话区** | 诊断结果呈现、改写四联对照、模拟面试逐题问答 | 单轮一问、追问、可中断 | 不做最终评分 |
| **报告区** | 五维雷达图、分数条、成长曲线、HTML 报告下载 | 只读 + 导出 | 不做二次编辑 |

### 2.2 为什么同页不跳转

学生在「改完一句、立刻想看分数变化」这个动作上停留最久。跳页会切断这个回路，还会让状态在页面间反复序列化。三块同页 + 服务端会话，是让「改 → 测 → 看」变成一次呼吸。

### 2.3 窄屏策略

纵向堆叠，功能不裁：工作区在上、对话区居中、报告区在下，用锚点跳转代替分页。不做响应式「隐藏次要功能」——演示常用手机竖屏录屏，藏掉的功能等于没做。

## 三、服务层：四项职责

### 3.1 路由与文件解析

- 解析 PDF / DOCX / 纯文本 → **五类字段**（基本信息 / 教育 / 经历 / 项目 / 技能）
- 扫描件识别为图片型 → **显式提示改用粘贴**，不得静默降级为「读不懂但假装读完」
- 解析结果落到结构体，不保留整段原文作为唯一产物

### 3.2 会话状态

服务端持有 session，至少包含：

| 字段 | 用途 |
|---|---|
| `resume_version` | 简历版本号，确认即升，可回溯 |
| `target_role` | 会话内锁定的目标岗位 |
| `jd_locked` | 抽成五字段后锁存的 JD，诊断全程共用 |
| `fact_sheet` | 当前事实清单（含版本号） |
| `module` | 当前所处模块（诊断 / 面试 / 复盘） |
| `round_no` / `layer` | 面试轮次与当前追问层 |
| `anchored_fact_id` | 本题锚定的事实编号 E1、E2… |

刷新不丢、不同访客不串数据。匿名标识只用于续接会话，**不等于账号**。存放方案取舍见 [`01-需求分析.md`](01-需求分析.md) 附录 A.4。

### 3.3 模型网关

- 密钥**只存在于服务端环境变量**，前端不接触、不持有、不可见
- 三段指令按模块拼接后调用，不把全部指令一次性塞给模型
- 温度参数与评分量规写在系统设计说明里，评审会翻

### 3.4 报告渲染与导出

复盘结果先出 JSON（结构见 [`03-逻辑梳理.md`](03-逻辑梳理.md) 第五节），再由服务端渲染 HTML：五维雷达图、分数条、逐题点评、卡点清单、成长曲线。同一份 JSON 同时供前端展示与文件导出，避免两份真相。

### 3.5 模块边界原则

1. **模块之间只通过结构化数据衔接。** 唯一交接物是「事实清单」，其余一律走 session，不靠模型记忆。
2. **模块内部不写人设。** 人设与引导语属于表现层，指令只写方法与约束。
3. **每个模块自带拒答规则。** 见 [`03-逻辑梳理.md`](03-逻辑梳理.md) 第六节。
4. **一个模块只做一件事。** 诊断不负责改写落地，面试不负责评分汇总。

## 四、逻辑层：三段系统指令

### 4.1 三段划分

| 指令文件 | 承载模块 | 输入 | 输出 |
|---|---|---|---|
| `prompts/diagnosis.md` | 简历诊断 + 定向改写 | 五类字段简历、锁定的岗位与 JD、`scoring-rubric.md` | 职业能力五维分数与加权总分（键名与公式见 01 附录 A.5）、每维≤3 条问题（附原文引用）、四联改写对照 |
| `prompts/interview.md` | 模拟面试 | 六字段事实清单、场景、轮次、`it-question-bank.md` | 逐题问答，每题标注锚定的事实编号与当前层 |
| `prompts/review.md` | 复盘出报告 | 问答记录、事实清单、`scoring-rubric.md`、`report-template.md` | 附录 A.1 定义的 JSON + HTML |

### 4.2 每段的写法：角色 / 流程 / 禁令

三段指令统一按三层写，**禁令单列，不与流程混写**：

```
# 角色     —— 你是谁、在什么环节、对谁说话
# 流程     —— 固定的步骤顺序与每步的输出格式
# 禁令     —— 做不到就停，明确列出「不许做什么」
```

混写的典型后果：禁令埋在流程中段，模型读到后半段已经忘了前半段的约束，于是「改写不新增事实」这条最关键的规则最先失守。

### 4.3 为什么是三段，不是六段或一段

判断标准只有一条：**用户会不会单独发起这个请求。**

| 方案 | 判断 |
|---|---|
| 拆成六段（解析 / 诊断 / 改写 / 出题 / 追问 / 复盘） | ❌ 把「流程步骤」当「模块边界」。解析与诊断是连续动作，拆开后每段都薄，还要互相递半成品 |
| 只写一段 | ❌ 三种口吻（耐心改写 / 施压追问 / 客观评分）混在一个指令里会串味，且无法单独调参 |
| **按三块页面切三段** | ✅ 三段各有独立的触发入口、独立口吻、独立产出格式、可独立版本替换 |

## 五、资产层：server/kb/（运行时）与 references/（源头资料）

> **运行时知识库只读 `server/kb/*.json`**（`knowledge.py` 只扫这个目录）：`roles.json`（岗位基线）、`questions.json`（题库）、`anchors.json`（评分锚点）、`writing.json`（改写句式），由 `server/kb/build.py` 从源头资料生成。`references/` 下的 Markdown 是设计期整理的源头稿，**不进运行链路**——改知识内容要先改源稿或直接改 JSON，别只改 `references/` 就以为生效。

### 5.1 资料清单

| 文件 | 内容 | 谁在用 | 维护 |
|---|---|---|---|
| `scoring-rubric.md` | 职业能力五维分档与行为锚点、面试能力五维量规 | 诊断 / 复盘 | 队长 |
| `field-schema.md` | 简历五类字段定义与解析规则 | 解析 | 后端组 |
| `job-catalog.md` | 8–12 个常见校招岗位基线（五字段） | 诊断 | 简历组 |
| `sentence-bank.md` | 改写句式库、动词替换表 | 定向改写 | 简历组 |
| `it-question-bank.md` | 题库（岗位 / 难度 / 考察点） | 面试 | 面试组 |
| `star-method.md` | STAR 判定与示例 | 面试 / 复盘 | 面试组 |
| `fact-schema.md` | 事实清单六字段与校验规则 | 诊断 / 面试 | 队长 |
| `report-template.md` | 报告 JSON 与 HTML 模板 | 复盘 | 后端组 |
| `gap-rules.md` | 卡点判定与回写规则 | 复盘 / 二次训练 | 队长 |

**改一份资料不动代码**，这是资料独立成目录的全部理由。

### 5.2 为什么知识库不能作运行时依赖

平台知识库的授权绑定在创建者账号上，调用凭据不能随作品分发，网页访客也进不了该知识库的空间。因此：

- 凡需要学生用到的资料，**开发阶段一次性采集**，落成 `server/kb/` 下带版本号的 JSON 随代码发布（源头整理稿可存 `references/`，经 `build.py` 生成 JSON）
- 更新时重新采集并提升版本号，**不做运行时实时检索**
- 真实学生简历、招聘平台抓取的页面、培训机构付费资料，三类材料不进入项目

### 5.3 三条纪律

1. **来源可溯**：每份资料标注出处与整理人角色（不写真实姓名）。
2. **样本必须自造或深度脱敏**：这是隐私红线，也是匿名红线。
3. **宁少勿杂**：一份高质量样本胜过十份泛泛资料；资料污染会直接放大成诊断错误。

## 六、数据流

### 6.1 主链路

```
上传 / 录入
   │
   ├─ 解析 → 五类字段（服务端）
   │
   ├─[诊断]→ 锁岗位 + JD → 五维分数 + 逐条问题 + 四联改写
   │                        └──→ 产出【事实清单】v1
   │
   └─[面试]→ 开场三确认 → 逐题单问、沿五层追问 → JSON 报告
                            └──→ 卡点回填【事实清单】v2
```

### 6.2 两条闭环

- **简历闭环**：诊断 → 改写 → 再诊断（五维分数变化即价值证明）
- **面试闭环**：按清单追问 → 复盘 → 缺口回填 → 下一轮只练薄弱项

两条闭环共享同一个数据结构：**事实清单**。它不是岗位卡——岗位卡来自 JD，事实清单来自简历诊断的产物。用户先改简历再练面试时，上下文正是靠它延续，而不是靠会话记忆。

### 6.3 唯一交接物

```
diagnosis ──产出──▶ fact_sheet ──只读──▶ interview
                        ▲                    │
                        └──── 卡点回写 ──────┘
```

不靠会话记忆衔接——记忆会漂移、会串味、换个会话就没了；结构化的清单不会。

## 七、部署与运维

### 7.1 部署形态

| 项 | 形态 |
|---|---|
| 访问方式 | 发布后获得公网链接，浏览器打开即用，无需注册与安装 |
| 运行环境 | 前端静态页面 + 单进程后端服务 |
| 密钥 | 服务端环境变量，不入库（`.env` 已在 `.gitignore`） |
| 数据 | 演示数据全部虚构，位于 `data/samples/` |
| 会话 | 服务端内存 / 轻量持久化，按匿名标识隔离 |

### 7.2 上线检查表

- [ ] 三块页面同页联通，窄屏纵向堆叠功能不裁
- [ ] 五类字段解析在三类样本（单页 PDF / 双页 DOCX / 扫描件）上跑通，扫描件能明确提示
- [ ] 同一简历连跑两次诊断，各维波动 ≤1 分、总分波动 ≤5 分（1–10 分制，见 01 附录 A.5）
- [ ] 改写十条比对原文，事实增量为零
- [ ] 三场景参数差异可观测（压力面层数上限 ≥4、出现直接质疑句；其余两场 ≤3 且不质疑）
- [ ] 报告导出 HTML 与页面展示一致
- [ ] 刷新页面会话不丢，换设备能按匿名标识续接
- [ ] 全部截图已脱敏；`raw/`、`private/`、`*.personal.*` 未入库
- [ ] 密钥不在前端任何位置出现
