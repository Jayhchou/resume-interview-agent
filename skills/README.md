# 技能目录

每个技能一个子目录，结构固定：

```
skills/
└── <技能名>/
    ├── SKILL.md        职责、触发条件、输入输出契约、执行步骤
    ├── references/     案例库、题库、量规等素材（由对应 owner 维护）
    └── scripts/        需要确定性计算时的脚本（可选）
```

## 技能清单

| 技能 | 状态 | 负责角色 | 说明 |
|---|---|---|---|
| `resume-coach` | 待建 | 简历组 | 解析 → 五维诊断 → 定向改写 |
| `interview-coach` | 待建 | 面试组 | 按场景出题 → 逐层追问 → 结构化复盘 |

两个技能由同一个专家挂载：

```json
"skills": ["./skills/resume-coach", "./skills/interview-coach"]
```

## 编写约定

1. **只写方法与约束，不写人设。** 人设属于入口层（见 `../expert-prompt.md`）。
2. **技能之间只通过结构化字段衔接。** 交接物是「候选人事实清单」，定义见 [`../docs/03-逻辑梳理.md`](../docs/03-逻辑梳理.md) 第四节。
3. **每个技能自带拒答规则。** 例如 `resume-coach` 遇到「帮我编一段实习」必须拒绝。
4. **一个技能只做一件事。** 诊断不负责改写，追问不负责评分。
5. **`SKILL.md` 只由托管人统稿。** 素材（references）由各自 owner 直接提交，互不干预。

详细边界见 [`../docs/02-架构设计.md`](../docs/02-架构设计.md) 第三节。
