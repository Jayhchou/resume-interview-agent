# 简历陪练 · 智能体应用

面向高校毕业生的**简历诊断改写**与**模拟面试训练**智能体。在腾讯 WorkBuddy 平台上构建，以「专家（入口）+ 技能（能力）+ 知识库（依据）」的形态交付，通过专家分享链接访问。

> 参赛作品仓库。所有文档、截图、代码**不含任何个人身份信息**。

---

## 一、解决的核心问题

应届生简历普遍是自我评价式的空话，缺可验证证据与岗位匹配度；模拟面试几乎没有低成本的一对一机会，学校就业指导一位老师对数百名学生，只能做群体讲座。本项目把「诊断 — 改写 — 演练 — 复盘」做成闭环，让一对一陪练人人可用。

## 四、协作规则（团队必读）

### 4.1 关键限制：专家本体不可协作编辑

WorkBuddy 的专家是**账号绑定的云端配置**，且「分享」出去的是**副本**——成员通过链接召唤的是一份独立拷贝，任何人修改都不会回传给其他人。因此：

1. **专家本体只有唯一托管人**（队长账号）可修改。其他人提出修改建议，或在自己的副本上试验，结论汇总给托管人合并。
2. **分享链接绑在托管人账号上**。专家一旦删除无法恢复，已分享的链接立即失效。项目期间不得删除专家、不得更换账号。
3. **`expert-prompt.md` 是唯一备份**。托管人每次在平台上改完配置，必须同步回本文件并提交一次 commit，说明改了什么、为什么改。

### 4.2 可以正常协作的部分

以下内容是真实文件，走标准分支 / PR 流程：

- `skills/` 下的技能文件（markdown + 脚本）
- `docs/` 下的文档
- `assets/` 下的素材

### 4.3 匿名约定（硬性）

仓库为公开仓库，且赛事要求提交材料不得出现任何身份信息。以下内容**一律禁止**进入本仓库：

- 真实姓名、学号、院校名称及简称、指导教师姓名
- 手机号、邮箱、微信号、身份证号等联系方式
- 含上述信息的原始简历样本（脱敏后放入，或只放结构化字段）

截图入库前逐张检查：界面头像与昵称、输出中的本地文件路径、简历正文中的姓名与电话。

### 4.4 提交信息规范

```
<类型>: <一句话说明>

类型：feat 新增能力 / fix 修正 / docs 文档 / prompt 提示词变更
示例：prompt: 简历诊断增加"量化证据缺失"判定项
```

## 五、快速开始

1. 阅读 `docs/01-需求分析.md` 确认自己负责的需求域
2. 阅读 `docs/02-架构设计.md` 找到对应的技能边界
3. 修改技能文件 → 提 PR → 平台组 review → 托管人同步到平台
4. 平台改动后，托管人更新 `expert-prompt.md` 并提交
